# Upgrading to 0.21

What changes for a project on 0.20. Before deploying it:

1. **Know what changed in the API.** A test holds these three lists to the exports themselves.

   `CliIo` holds `cwd`, `out`, `err`, `run` and `confirm` alone. 0.20's `CliIo.readPgObjects`, `CliIo.replayPgHistory`, `CliIo.readyPgDev` and `CliIo.locatePeer`, seams comb's own tests fake and typed by its internals, are gone from it, and `runCli` reads none of them from an io that carries one. `Run`, `RunOptions`, `RunResult` and `BinPeer`, which type `run`, are exported from `@workerstack/database/cli` as from `/migrate`. **Fix:** drop such a field from the io you pass; comb finds its peers, reads Postgres and readies the dev database itself. Every type a public declaration names is now one you can import, from the subpath whose function or type names it, or from the one subpath that owns a type several share (the column options from `/sqlite/constraints`, `CombError` and the constraint map from the root, the list query types from `/query`), so a helper typed around comb's API names what it takes and returns; a test holds each subpath to its list, and the few kept internal to theirs, each with its reason. `ListQuerySchema`, `RetrieveQuerySchema`, `paginateMerged` and `createRetrieveQuerySchema` changed only in the names their declarations give types they reach: `ListQueryRequest`, `RetrieveRequest` and `PaginationResponse`, exported under those names. `createListQuerySchema` and `queryHelpers` change in those names and more: `queryHelpers.filterValue` and `filterValues` take an `operator` (step 34), and `createListQuerySchema`'s `limits` takes `undefined` for any key (step 21) and its config reserves `tiebreak`, as below. `@workerstack/database/query` exports the functions `queryHelpers` groups, `paginate`, `drizzleListOptions`, `drizzleProject`, `extractFilterValue` and `extractFilterValues`, so a project that emits declarations can export `queryHelpers`, or a helper returning what one of them returns, where 0.20 failed it with TS2742, its type naming a file only comb's `types/` folder holds. `processIo` and `runCli` change with `CliIo`. The options of `run`, which `DrizzleExportOptions`, `SchemaDiffOptions`, `checkAtlasInstalled`, `createD1Provider`, `createProvider`, `exportDrizzleSchema`, `generateSchemaDiff` and `getAtlasVersion` take, gain an optional `peer`, the `BinPeer` a command runs (step 2).

   `generateManifest`'s config no longer takes `ManifestConfig.filePrefix`, which it never read: the manifest is written to `output` alone, as in 0.20. 0.20 exported the function but not its config type, so `ManifestConfig` is listed as a new export by name only; its `output` is unchanged. A call whose object literal still passes `filePrefix` fails to compile (TS2353). **Fix:** drop `filePrefix` from the call.

   A built list's `pagination` gives `ListPagination.fit` in place of `ListPagination.mint`: `fit(row)` runs every check the cursor after `row` passes and returns what seals it, so `paginate` and `paginateMerged` check each row they serve and seal the last alone (step 85). Code that passes `pagination` on to `paginate` or `paginateMerged` is unchanged. **Fix:** call `pagination.fit(row)()` where you called `pagination.mint(row)`.

   `checkAtlasInstalled`, `exportDrizzleSchema`, `getAtlasVersion` and codegen's `analyze` return a promise: comb runs every process it starts (Atlas, wrangler, drizzle-kit, the tables loader) asynchronously, so a `SIGINT` or `SIGTERM` to comb reaches it while that process runs (step 56). A `Run` returns a promise too: comb's default runner, and each one you pass: as `CliIo.run` to `runCli`, as `DrizzleExportOptions.run`, `SchemaDiffOptions.run` or `ProviderDeps.run`, which `createProvider` takes, or as `createD1Provider(exec)`, `checkAtlasInstalled(exec)` or `getAtlasVersion(exec)`. **Fix:** `await` each call, and make a runner you pass `async`; it answers the same `RunResult` as before.

   `CombError`, which `classifyD1Error`, `classifyPgError`, `classifySqliteError` and `constraintError` return, gains `toJSON()`, the body a client gets: `column`, `errorKey`, `status`, `statusKey` and `table`, the two optional ones left out when unset. Its fields are defined, not assigned, so a project on Bun whose tsconfig sets `useDefineForClassFields: false`, as legacy decorators need, keeps `column` in the JSON body and in a spread; 0.20 dropped it there, into JavaScriptCore's own `Error.column`. **Fix:** none.

   A declared `pattern` holding `\d`, `\w`, `\s` or `\b`, or a capital of one, is refused at codegen, naming the column and the class to write out (`[0-9]` for `\d`, `[A-Za-z0-9_]` for `\w`): ECMAScript, Go's RE2 and Rust's `regex` read those escapes as other sets (RE2's `\s` is ASCII, Rust's `\d` and `\w` are Unicode), so one published pattern meant three rules. `patterns.E164_PHONE` writes its digits as `[0-9]` for the same reason, so it stays a pattern codegen takes. comb's own patterns write their classes out too: an id's refuses each ECMAScript blank by name, and a plain `date`, `timestamp` or `time` column publishes comb's ISO pattern, zod's own with each `\d` as `[0-9]`. **Fix:** write the class the refusal names.

   A declared `pattern` holding `.` outside a class is refused at codegen as well, naming `[^\n\r]`: ECMAScript's `.` refuses `\r`, U+2028 and U+2029, which RE2's and Rust's take. So is one holding a lookaround (`(?=`, `(?!`, `(?<=`, `(?<!`) or a backreference (`\1` to `\9`, `\k<name>`), which neither engine compiles, so a Go or Rust validator refused the whole document of any API with that field, and so is one holding `\0`, an octal escape Rust's regex refuses. **Fix:** write the class meant, the rule without the lookaround or backreference, and NUL as `\x00`, which every engine reads as NUL.

   A declared `pattern` holds only the escapes and classes Go's RE2 and Rust's regex compile and read as ECMAScript does: a syntax character (`\.`, `\/`, `\[`, `\-` in a class), `\xHH`, `\t`, `\n`, `\r`, `\f`, `\v`, and `\p{…}` or `\P{…}` naming a General_Category as Go names it (`L`, `Lu`, `Nd`; not `Letter`, nor `Cs`, which Rust refuses). Codegen refuses any other, naming the spelling to write: `\u0041` as `\x41`, a `\u` past U+00FF as the character itself, `\cJ` as `\x0A`, and a script, binary property or `General_Category=` (`\p{Script=Greek}`, `\p{Emoji}`, `\p{ASCII}`) as the category or the ranges meant, as Go's RE2 compiles none of them and refused the whole document of any API with that field. It also refuses `[]` and `[^]` (write `[\p{L}\P{L}]` for any character), a `&&`, `--` or `~~` in a class, which Rust's regex reads as a set operation, a `[` in a class, which it reads as a nested class (write `\[`), a count past 1000, which Go's RE2 does not compile, and a literal U+2028 or U+2029, which the published source writes as a `\u` escape (write `\p{Zl}` or `\p{Zp}`, which every engine reads as that character alone). The check reads the source comb publishes, the engine's own. A `\p{…}` or `\P{…}` publishes by name, so each engine reads the category in its own Unicode version: Rust's regex 1.13 and Node 22 read U+A7CE, a letter since Unicode 17, as no letter, and Go 1.27 and Node 24 read it as one. A non-ASCII character publishes as itself on Bun as well; 0.20 published it there as the `\u` escape Bun writes in a regex literal, which Go's RE2 refuses. **Fix:** write the spelling the refusal names.

   It holds only the grammar Go's RE2, Rust's regex and Node 22.13 read as one rule: groups `(`, `(?:` and `(?<name>`, each name ASCII letters, digits and `_`, a letter or `_` first, and used once, and counts with no leading zero. Codegen refuses an inline modifier such as `(?i:`, a group name used twice, which Node 22 refuses, and a count such as `{02}`, which Go's RE2 reads as the text `{02}` (write `{2}`). It refuses nested counts whose product passes 1000, such as `(?:a{2}){501}`, which Go's RE2 does not compile, and nesting past 250 levels, which Rust's regex refuses. It also refuses counts and classes whose compiled size passes Rust's 10 MiB, which a validator there refuses: `\p{L}` repeated about 80 times reaches it, so repeat a large class with `+` or `*` and bound the length with `max`. And it refuses a lone surrogate, which a JSON document cannot carry as a character. **Fix:** rewrite a refused pattern in this grammar: `{2}` for `{02}`, and `+` or `*` with `max` for a long repeat.

   `ManifestColumn` gains `sqlType`, the column's SQL type with its modifier as drizzle writes it (`timestamp(3) with time zone`, `interval day`, `numeric(3, -2)`): a plain Postgres column's rule reads the modifier, so `kind` alone (`PgTimestampString`) did not tell a `timestamp` from a `timestamptz(3)`. It gains `dimensions` too, an array column's dimensions, 0 for a column of one value; an array column's `sqlType` is its element's. With `nullElements` (below), `ManifestColumn` requires all three, so code that builds one, such as a manifest fixture, fails to compile (TS2741); the manifest's `v` is 3 for the relation change in step 27. **Fix:** a `ManifestColumn` you build sets `sqlType`, `dimensions` and `nullElements`.

   A Postgres array column's write DTO takes a null element only where the column's drizzle type declares one: `text("tags").array()` is `string[]` in the table's `$inferInsert`, so its create and update refuse `["a", null]`, which 0.20 took and handed an insert typed to never hold it. Declare a nullable element with `$type<E>()`, which types the element: `text("tags").array().$type<string | null>()`, or `integer("grid").array("[][]").$type<number | null>()` for every level of a grid. A read still takes a stored null element, whatever the type says. Codegen reads the type with TypeScript's checker from the tables file, under its tsconfig with `strictNullChecks`; an array column whose `$inferInsert` type or element type TypeScript cannot resolve, such as a `$type<E>()` naming a type never declared, fails naming the table and column, and picks no default. Any other type error in the tables file is left to your typecheck. `FieldMeta` gains an optional `nullElements`, and `ManifestColumn` a required one (above). **Fix:** add `$type<E | null>()` to an array column whose elements are null by design.

   `parseOrder()` returns `null`, and the list query schema answers a 400 naming the entry, for an `order` entry with whitespace around it (`title.asc, created_at.desc`, a tab, an `order` of spaces alone) or a field named twice (`title.asc,title.desc`), which 0.20 trimmed or let the last entry win in `sortOrderBy` while `parsedSort` kept both (step 33). **Fix:** send each `order` field once, with no whitespace around an entry.

   `classifyMigration`, `parseMigration` and `extractDropStatements` take `kind`, the `TargetKind` a file applies to (`"d1"`, `"local"` or `"sqld"`, step 3), in place of 0.20's `ClassifyOptions.d1` (`d1: true`). A call passing `{ d1: true }` fails to compile (TS2353), as does a variable holding only `d1` (TS2559); one whose options object also sets another field compiles, and throws a TypeError naming `d1` when it runs, as any option these functions do not take does, in JavaScript too. **Fix:** pass `kind: "d1"` where you passed `d1: true`, and drop `d1: false`.

   Every optional property comb declares takes `undefined`, as comb reads a key set to `undefined` as the key left out: a project under `exactOptionalPropertyTypes` can forward a value that may be unset, `createUlidFactory({ now: env.NOW })` or `createListQuerySchema({ pagination: { maxLimit: env.MAX } })`, where 0.20 refused it with TS2379 or TS2375. `c.enum` reads a state set to `undefined` the same way: `{ initial: undefined }` records no state machine, where 0.20 recorded one that named no state. `D1DatabaseLike.withSession` is a property now, so TypeScript checks a fake's `withSession` strictly: one that takes `constraint: string` compiled on 0.20 and fails on 0.21 (TS2322), while a real `D1Database` fits. **Fix:** a D1 fake's `withSession` takes `string | undefined`.

   `ListExtra` and `ListExtras` gain `_combKeyTexts` and `_combTextKeys` (steps 60, 63), and `DrizzleListOptions`'s `extras` returns them on a sorted list; `createCursor` takes `asRead`, the sort fields its list binds as read, and `carried`, the sort fields whose value is the stored text the list carried in place of the value as read (`_combKeyTexts`), which the cursor flags so the next page binds that text as itself; `DecodedCursor.carried` is new and required, that flag per sort value, so a `DecodedCursor` you build, such as a `readCursor` test double, fails to compile (TS2741). A cursor also carries the value the row read for each key the list binds as another, which `readCursor` returns in that value's place. `ListQueryConfig`'s `limits` and `validateFilter`'s third argument take `undefined` for any key (step 21). **Fix:** a `DecodedCursor` you build sets `carried`, one boolean per sort value; `false` for a value as read.

   `tiebreak` is a reserved list key, as the parsed output carries it: `createListQuerySchema` throws on an `extend` shape holding a field named `tiebreak`, which 0.20 took. **Fix:** rename the field.

2. **Install `wrangler` and `drizzle-kit` in the project that runs comb.** comb now finds each in the project, from the working folder up, checks that package's version and runs its own bin by path: `wrangler` on `node`, `drizzle-kit` on the runtime running comb. 0.20 checked the `wrangler` comb's own install resolved and then ran whichever `wrangler` was first on `PATH`, so in a workspace the version comb checked could differ from the one it ran. `PATH` no longer counts: a `wrangler` or `drizzle-kit` installed only globally, or reached only through `node_modules/.bin`, is refused with the range and the install, and a workspace runs the copy it installed itself. `comb migrate diff` runs `drizzle-kit` by its bin path on the runtime running comb, so it needs no Bun under Node: 0.20's `bun drizzle-kit` followed the bin's `node` shebang, and ran it on Node. The `run` you pass `createD1Provider`, `createProvider` for a `d1` config, or `exportDrizzleSchema` sees the same: its command is the runtime (`node`, or the running comb's `process.execPath`) and its arguments start with the bin's absolute path, as in `node ["<project>/node_modules/wrangler/bin/wrangler.js", "d1", "execute", …]`, where 0.20 gave `wrangler ["d1", "execute", …]` and `bun ["drizzle-kit", "export", …]`; under Bun, `drizzle-kit`'s options also carry `BUN_BE_BUN=1` in `env`, so an app compiled to one executable runs Bun on the bin rather than itself. Codegen's `analyze`, `loadPostgresParser`, `createLibsqlProvider`, `createTursoProvider` and `createProvider` for a libsql or Turso config, every D1, libsql and Turso command but `migrate diff` (`status`, `check`, `apply` and `baseline`), every Postgres command but `migrate status`, a SQLite `migrate diff` whose comb.config.ts declares FTS, and `comb --version`, which reads comb's package.json from disk, are refused in such an executable, each with the reason: codegen and an FTS diff run a child process, which cannot read the modules the executable embeds, and the others load a peer from the project (`wrangler`, `@libsql/client`, `libpg-query` or `postgres`), which the executable cannot, so run them with bun or node. `createD1Provider` and `createProvider` for a `d1` config find `wrangler` from `process.cwd()` and `exportDrizzleSchema` finds `drizzle-kit` from its `cwd`, each refused before your `run` is called when that project lacks it. **Fix:** add `wrangler` and `drizzle-kit` to the project's dependencies, run a command refused in a compiled executable with bun or node, and match a `run` fake on the bin path where it matched `wrangler` or `bun`.

3. **On libsql over a network and on Turso, take out what the server refuses.** A libsql URL of any scheme but `file:` and `:memory:`, and every Turso database, reach a libsql server (sqld), which refuses at parse a pragma outside its lists (one for reading a pragma, one for setting it), a pragma with a quoted name, `ANALYZE`, `ATTACH` and a `TEMP` object, and `load_extension()` when it runs. 0.20 passed them at check and apply then failed on them; 0.21 refuses them at check with no override, naming "libsql server (sqld)". **Fix:** remove the statement from the file; for a connection pragma 0.20's step 3 told you to add, the server runs the file without it. Such a target's files now apply through the run's one client.

4. **Read bcrypt's limit on `passwordText` as `x-comb-maxUtf8Bytes`.** `passwordText({ hash: "bcrypt" })` and `passwordText.typed({ hash: "bcrypt" })` publish `x-comb-maxUtf8Bytes: 72`, the UTF-8 bytes of the string itself, where 0.20 published `x-comb-maxBytes: 72`, which meta-contract §2.1 defines as the bytes of a value's JSON text, quotes and escapes included: a reader applying it as defined refused every 71- or 72-byte password comb took. Both forms publish `x-comb-transform: ["nfc"]`, so a reader normalizes before it counts, as comb does: 0.20's `minLength` and `maxLength` read without it refused a long password typed decomposed and took a short one. A password out of bounds is now zod's `too_small` or `too_big` issue with its `minimum` or `maximum`, bcrypt's bytes a `too_big` with `maximum: 72`, where 0.20 gave a `custom` issue with neither. `passwordText({ hash: "bcrypt", min })` with a `min` past 72 throws a TypeError at build, as no password passes it. **Fix:** a client that reads `x-comb-maxBytes` from a password schema reads `x-comb-maxUtf8Bytes` and applies the `nfc` transform first; error handling that matched the `custom` messages matches `too_small` and `too_big`.

5. **Set a tenant column once.** A column declared `{ tenant: true }` is out of the generated update DTO and listed `immutable`, in the stamp and the manifest, whatever it references: 0.20 kept only a tenant that was a non-`mutable` reference out of update, so a `c.text` or `c.integer` tenant, or any tenant that references nothing, took a body that moved the row to another tenant, while `tenantColumn` named it. `{ tenant: true, mutable: true }` fails codegen, naming the column. **Fix:** regenerate; move a row between tenants with a statement of your own, not a PATCH body; drop `mutable` from a tenant column.

6. **Send a Postgres value its type modifier keeps.** A plain drizzle column's write DTO reads its modifier as Postgres does: a `time(p) with time zone` takes an offset (0.20 refused every value with an offset and took a local time); a precision refuses a longer fraction of a second on a time, timestamp or interval, which Postgres rounds, `timestamp(0)` taking `23:59:59.6` into the next day; an interval with fields refuses a part below the last (`PT1H` into `interval day`, `P1Y2M3D` into `interval year to month`), which Postgres drops without an error; a `numeric(p, s)` with `s > p` takes its values (0.20 refused all of them) and one with `s < 0` takes only a whole number ending in `-s` zeros below `10^(p - s)` (0.20 took `123456`, a 22003, and `99949`, stored as `99900`). An `interval({ precision: 0 })` refuses any fraction of a second, which 0.20 took: drizzle-kit creates the column as a plain `interval`, which keeps the fraction, so the DTO alone holds the whole seconds it declares, and a column created as `interval(0)` would round it. **Fix:** regenerate; send each value at its column's precision and fields.

7. **Run Atlas >=1.2.0 <2.** comb now reads `atlas version` before the first I/O of each command that runs Atlas, every one but `status` on SQLite, libsql, Turso and D1 and D1's `baseline`, and refuses an Atlas outside that range, or missing from `PATH`, naming it with its install page, in the same refusal as any npm peer the command lacks; 0.20 checked no version, and every command but `diff` failed later with `atlas migrate hash failed: atlas: command not found`. `comb migrate status` on Postgres needs Atlas as the other commands do. A SQLite `comb migrate diff` whose comb.config.ts declares FTS now names `ts-morph` with `drizzle-kit` before any process. comb no longer sets `PGSERVICEFILE` for Atlas, which before v1.2.0 failed every Postgres command on it. **Fix:** put an Atlas from 1.2.0 below 2 on `PATH` wherever comb runs, for Postgres's `migrate status` too.

8. **Drop the type argument from `getHandle`.** `ShardRouter.getHandle(mapping, env)` now types the shard's handle by the env it is passed: the type the env's `SHARD_DB_*` bindings have, which `wrangler types` writes as `D1Database`, so the handle goes to `drizzle()` as it is. A binding bound in only some of the config's environments, which `wrangler types` writes optional (`SHARD_DB_1?: D1Database`), is taken too, and `getHandle` throws `Missing D1 binding` for one absent at run time. An env typed by a string index signature gives the binding its index holds, `Record<string, D1Database>` a `D1Database` and `Record<string, unknown>` the structural `D1DatabaseLike`, and one that holds no D1 binding, such as `Record<string, string>`, fails to compile; an env whose known keys hold no `SHARD_DB_*` binding fails to compile.
