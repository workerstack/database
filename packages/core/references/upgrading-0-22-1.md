# Upgrading to 0.22.1

What changes for a project on 0.22. No export changed. Before deploying it:

1. **Expect a page past `maxPage` to be `page_too_deep` at every size.** A page number past `maxPage` and above 2^53 was a validation issue, and one past 1e308 read as Infinity and answered `invalid_page`; now every page past `maxPage`, however many digits it has, throws `CombError` `page_too_deep` (400), as a page just past it already did. **Fix:** none, unless a client matched `invalid_page` or a validation issue on a huge page: match `page_too_deep`.

2. **Expect `select=*,name` to refuse an unknown name.** The wildcard was expanded before the other names were checked, so `select=*,secret` dropped `secret` and answered 200 where `select=secret` is a 400. Each name beside `*` is now checked against the declared fields first, at the root and in a relation, and an unknown one is the same 400 it is alone. **Fix:** a client that sent a stale field beside `*` drops it.

3. **Expect a filter's empty member refused.** A trailing comma (`a.eq.x,`), two commas together, or an empty list member (`a.in.(x,,y)`, `a.nin.(,)`) was taken, the empty member dropped; now each is `Invalid filter syntax: empty member at position N`, N counted in the string the client sent. `in.()` stays the one empty list. **Fix:** a client that built a filter by joining with a trailing comma stops sending it.

4. **Expect a deeply nested filter to be a 400, not a 500.** The parser recursed once per `or()` or `and()` group and checked `maxDepth` only on the finished tree, so a few thousand levels overflowed the stack and answered 500. It now refuses the first group past the cap where it opens, with `Filter nesting too deep at position N (max D)` in place of `Filter nesting too deep: 4 (max 3)`, and reads no further than 256 levels whatever `maxDepth` says: a `maxDepth` above 256 acts as 256. `parseFilter` returns `null` past that depth instead of throwing. **Fix:** a client or test that matched the old message matches the new one.

5. **Expect every row once from a cursor over a column of mixed storage classes.** A key held apart, in an untyped or BLOB column holding TEXT that reads as a number beside numbers, was bound through `cast(? as real)` or `cast(? as integer)`, whose affinity made SQLite compare the TEXT `'10'` as the number 10: a cursor walk skipped rows ascending and looped descending. The bound value now carries no affinity. **Fix:** none.

6. **Expect pages by number that 0.21 refused to serve.** Since 0.21 a list answered 500 (`sort_not_wired`) for any page holding a row no cursor can hold (a key too long for a cursor, an Invalid Date as read, a rounded integer, a JSON key, a held storage class), even a page asked for by number or a last page, which mint no cursor from it. A page served by cursor still checks every row it serves, as item 85 of 0.21 says. A page by number now serves its rows, and when the last row, the one its next cursor would be minted from, is one no cursor can hold, its `nextCursor` is `null` while `hasMore` still says there is a next page by number. **Fix:** none; a client that pages by number pages on, and one that follows `nextCursor` stops where it is `null`.

7. **Expect the published `order` pattern to take what the parser takes.** The `order` pattern was written by hand beside the parser: it refused the empty `order` the parser reads as the default, and took as many entries as `maxSortKeys` even on a list with fewer fields, where an extra entry repeats a field the parser refuses. It is now built from the parser's own rule: it takes the empty value, takes no more entries than the list has sortable fields, and its description says each field may appear at most once and that an absent or empty `order` is the default. **Fix:** regenerate, so the published spec carries the new pattern; a contract test that sent `order=` expecting a 400 expects the default order.

8. **Expect a D1 check to name a table called by a keyword as a name.** The proof read every bare word of a file as a possible name, so the `TABLE` keyword in every file put a table named `table` in scope, and each table's own `CREATE TABLE` made it a child of every other: a schema with such a table copied everything into every proof. A bare keyword SQLite never takes as a name no longer counts. **Fix:** none; such a check takes about as long as one on a schema without that table.

9. **Expect check to refuse a file that leaves a view or trigger unable to run.** SQLite's `DROP TABLE` and `DROP VIEW` check none of the views and triggers that use what they drop, and the proof compiled only what a file made or changed, so a file dropping a view another view reads passed check and every later read of that view, or write to the trigger's table, failed. The proof now compiles, after each file, every surviving view and trigger that uses something the file dropped or changed, on bun:sqlite, libsql, Turso and D1, and refuses the file with no approval to override it, for example `0002_next.sql: after this file, view v2 cannot be read: no such table: main.v1; drop or change it in this file, or keep what it uses`. **Fix:** drop or change the dependent view or trigger in the same file, or keep what it uses.

10. **Expect an `INSTEAD OF` trigger for some of a view's writes to pass a D1 check.** The D1 proof compiled an insert, an update and a delete on a view for any trigger on it, so a file adding an `INSTEAD OF` trigger for one or two of those events was refused with `cannot modify v because it is a view`, though D1 applies it and runs its writes. A view now gets only the writes its triggers fire on. **Fix:** none.

11. **Expect a statement to keep a name that ends in a Unicode space.** The SQLite splitter trimmed each statement with JavaScript's `trim`, which strips U+00A0, U+3000 and the other spaces SQLite reads as part of a name, so comb applied a column `c` where SQLite makes `c<NBSP>`, and ran a statement SQLite refuses. It now trims SQLite's own whitespace alone, as the hash already did. **Fix:** none.

12. **Expect a history drizzle made to hold each file once.** A migrations table drizzle's migrator made gains `name` with no unique index, so two applies at once could both record and run the same file: a seed or a backfill ran twice and both exited 0. comb now adds a unique index on `name` where none holds it, and refuses, naming the files, a history that already records one twice. **Fix:** if apply refuses a history for a duplicate, delete the extra row after checking the file's effect ran once.

13. **Expect a Postgres check to leave another session's role and database alone.** Postgres records no creator for a role, a database or a replication slot, so the replay took any change to a name the file spelled for the file's own: a file of plain statements was refused when another session made a role or database it names during the replay, and the cleanup then dropped that session's role and database. A change to a name the file spells now counts only when the file's statements so far run code comb cannot read (a `DO` block, a `CALL`, an `EXECUTE`, or a call of a function outside `pg_catalog`), and a refused file's role, database or slot is left on devUrl's server and named in the refusal (`comb leaves role X added, database Y added, Z on devUrl's server, as another session may have made those changes: undo there each that is the file's`), where 0.21's item 66 dropped it. **Fix:** after such a refusal, drop on devUrl's server what the file made.

14. **Expect `SIGHUP` and `SIGQUIT` to stop comb as `SIGTERM` does.** Atlas runs in a process group of its own, so a hangup from a closed terminal no longer reached it, while comb ended at once on `SIGHUP` or `SIGQUIT`, printing no `Stopped by` line and leaving Atlas to finish the file in flight. All four of `SIGHUP`, `SIGINT`, `SIGQUIT` and `SIGTERM` now take 0.21's stop path. **Fix:** none.

15. **Read `stoppedBy` from `--json` when a signal stops apply.** Under `--json`, an apply a signal stopped printed no object, so a runner reading it recorded nothing applied. It now prints the one object it prints on any other end, with `applied` naming each file that committed, the signal in `stoppedBy`, and the `Stopped by` line in `refused`, for example `{"applied":["20260101000000_a.sql"],"database":"db","pending":["20260101000001_b.sql"],"refused":["Stopped by SIGTERM: applied 20260101000000_a.sql; not applied 20260101000001_b.sql"],"stoppedBy":"SIGTERM","unknown":[]}`, and still ends by the signal. The signal is any of `SIGHUP`, `SIGINT`, `SIGQUIT` and `SIGTERM` (step 14). On SQLite the `Stopped by` line now goes to stderr too. **Fix:** a runner reads `applied` from that object, and `stoppedBy` to tell a stop from a refusal.

16. **Expect a path of the wrong kind refused by name.** `comb migrate diff <database> <name>` refuses a name holding `/` or `\`, or `.` or `..` alone, with its usage, where Atlas failed on a file it could not open in comb's scratch directory. `--tables`, or comb.config.ts `tables`, naming a directory is refused as `tables <path> is a directory, not a file`, where loading it failed with `EISDIR`. A d1 provider's `wranglerConfig` naming a directory is refused as `wranglerConfig <path> is a directory, not a file`, where comb said the config binds no such database. **Fix:** give a diff a name alone, point `tables` at the module that exports the tables, and point `wranglerConfig` at the wrangler.json, wrangler.jsonc or wrangler.toml itself.

17. **Read `migrate diff --dry-run`'s exit 2 as a check that could not run.** A dry run exits 1 only for drift now; a failure that kept it from checking (Atlas or drizzle-kit missing or failing, an unreachable `devUrl`, a config or an argument comb refuses) exits 2, where 0.21 exited 1 for both. **Fix:** a gate that fails on any non-zero exit needs no change; one that acts on drift, by writing the migration or opening a pull request, acts on exit 1 alone.
