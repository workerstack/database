# Upgrading to 0.24

What changes for a project on 0.23. 0.23 moved comb to `@workerstack/database` and kept comb's names; 0.24 drops every one of them. Nothing reads an old name, so change them all in one upgrade. [Migrating from comb](../docs/migrating-from-comb.md) lists every name, old to new. Before deploying it:

1. **Know what changed in the API.** A test holds these three lists to the exports themselves.

   New exports: `CliTerminal`, `CodegenManifest`, `ColumnMetaKind`, `ConstraintFallback`, `DATABASE_META_KEY`, `DATABASE_META_VERSION`, `DatabaseDriverErrorKey`, `DatabaseError`, `DatabaseErrorKey`, `DatabaseMeta`, `DatabaseMetaInput`, `DatabaseMetaKind`, `DatabaseMetaStamp`, `EntityMeta`, `EntityMetaInput`, `FILTER_GRAMMAR`, `FilterFieldMeta`, `FilterGrammar`, `KeysetTiebreak`, `MigrateConfig`, `MigrateConnection`, `MigrateDialect`, `MigrateRun`, `QueryMeta`, `QueryMetaInput`, `SearchRefold`, `StatesMeta`, `carryDatabaseMeta`, `databaseDriverErrorKeys`, `databaseErrorKeys`, `databaseMeta`, `readDatabaseMeta`, `readEntityMeta`, `readQueryMeta`.

   Removed: `COMB_FILTER_GRAMMAR`, `COMB_META_KEY`, `COMB_META_VERSION`, `CombColumnKind`, `CombDatabaseErrorKey`, `CombEntityMeta`, `CombEntityMetaInput`, `CombError`, `CombErrorKey`, `CombFilterField`, `CombFilterGrammar`, `CombMeta`, `CombMetaInput`, `CombMetaKind`, `CombMetaStamp`, `CombMigrateConfig`, `CombQueryMeta`, `CombQueryMetaInput`, `CombStatesMeta`, `Connection`, `Dialect`, `Fallback`, `Manifest`, `Refold`, `Run`, `Terminal`, `Tiebreak`, `carryCombMeta`, `combDatabaseErrorKeys`, `combErrorKeys`, `combMeta`, `readCombEntityMeta`, `readCombMeta`, `readCombQueryMeta`. **Fix:** import each by its new name from the same subpath; [Imports and types](../docs/migrating-from-comb.md#imports-and-types) pairs each removed name with its new one.

   Changed: `AnalysisResult`, `ClassifyOptions`, `CliIo`, `CodegenConfig`, `ConnectionProvider`, `D1_HASH_TABLE`, `DatabaseCodegen`, `DrizzleExportOptions`, `DrizzleListOptions`, `FieldMeta`, `GeneratorContext`, `KeysetPosition`, `ListExtra`, `ListExtras`, `ListPagination`, `ListQuery`, `ListQueryResult`, `ListRow`, `MergedListQueryResult`, `OrmConfig`, `PAGE_DESCRIPTION`, `ProviderDeps`, `SchemaDiffOptions`, `TableMeta`, `analyze`, `applyListQuery`, `buildDerivedListQuery`, `buildListQuery`, `buildManifest`, `checkAtlasInstalled`, `classifyD1Error`, `classifyMigration`, `classifyPgError`, `classifySqliteError`, `constraintError`, `createBunSqliteProvider`, `createD1Provider`, `createLibsqlProvider`, `createProvider`, `createTursoProvider`, `defineCodegenConfig`, `defineConfig`, `deriveEntityMeta`, `drizzleListOptions`, `exportDrizzleSchema`, `extractDropStatements`, `extractSchema`, `fieldConstraintsOf`, `generateColumns`, `generateConstraints`, `generateDiagrams`, `generateDtos`, `generateEntities`, `generateEnumChecks`, `generateFieldNames`, `generateFts`, `generateFtsSql`, `generateManifest`, `generateOrm`, `generateRelations`, `generateRows`, `generateSchemaDiff`, `generateTranslations`, `getAtlasVersion`, `getSqliteColumns`, `getSqliteIndexes`, `getSqliteTables`, `introspectSqliteSchema`, `isExcludedFromUpdate`, `keysetSQL`, `orderByKeys`, `paginate`, `paginateMerged`, `parseMigration`, `processIo`, `queryHelpers`, `refoldStatements`, `resourceOutcome`, `runCli`, `splitSqlStatements`, `validateTables`.

   Each changed export keeps its shape: its declaration names a renamed type, such as `MigrateRun` (step 2), or a renamed member, `FieldMeta.combKind` now `FieldMeta.databaseKind`. **Fix:** none beyond the renames.

2. **Rename the nine bare-word exports.** An export that was one common word read as a Cloudflare or DOM type at the import site, so each now names its area: `Run` is `MigrateRun` in `./cli` and `./migrate`, `Terminal` is `CliTerminal`, `Dialect` is `MigrateDialect`, `Connection` is `MigrateConnection`, `Manifest` is `CodegenManifest`, `Fallback` is `ConstraintFallback`, and `Tiebreak` and `Refold` in `./query/sqlite` are `KeysetTiebreak` and `SearchRefold`. A lint now refuses a bare one-word export. **Fix:** rename each import ([Bare exported words](../docs/migrating-from-comb.md#bare-exported-words)).

3. **Run `database`, not `comb`.** The bin is `database` (`database codegen`, `database migrate`), the config files are `database.config.ts` and `database.migrate.config.ts`, the working folder is `.database/`, the codegen record is `.database.codegen.gen.json`, and the unsafe-change flag is `--database:allow-unsafe`. **Fix:** rename the files and the folder, and change each script and CI step that calls `comb` ([Install and run](../docs/migrating-from-comb.md#install-and-run)).

4. **Rename the environment variables.** Each `COMB_*` variable is `DATABASE_*` (`DATABASE_ATLAS_URL`, `DATABASE_ATLAS_DEV_URL`, `DATABASE_TEST_PG_URL` and the rest); an old name is not read. **Fix:** rename each in `.env` files and CI ([Environment](../docs/migrating-from-comb.md#environment)).

5. **Regenerate for the `x-database-*` extensions.** The OpenAPI extensions codegen writes are `x-database-*`, not `x-comb-*`, and a spec from 0.23 still carries the old keys. **Fix:** run `database codegen` again, and update any tool that reads an `x-comb-*` key ([OpenAPI extensions](../docs/migrating-from-comb.md#openapi-extensions)).

6. **Rename the D1 tracking tables before the first deploy.** The migrator records into `_database_migration_hashes` and `_database_migration_hash_intents`; it does not read `_comb_migration_hashes` or `_comb_migration_hash_intents`, so a database migrated before 0.24 would apply every migration again. **Fix:** rename both tables once per database, outside the migrator, with the two `wrangler d1 execute` commands in [D1 tracking tables](../docs/migrating-from-comb.md#d1-tracking-tables), and check that the second prints no rows.

7. **Expect a page cursor from 0.23 to be refused.** A cursor's key is derived from `CURSOR_SECRET` and a label that named the package, and that label changed, so a cursor handed out before the upgrade is `invalid_cursor` (400), as a tampered one is. The list extras that carry a cursor's position are renamed: `ListExtras._combId`, `ListExtras._combKeyTexts`, `ListExtras._combKeyTypes`, `ListExtras._combTextKeys` and `ListExtras._combAnchorGone` are `_cursorId`, `_cursorKeyTexts`, `_cursorKeyTypes`, `_cursorTextKeys` and `_cursorAnchorGone`. **Fix:** a client that gets `invalid_cursor` starts its list again from the first page ([Page cursors](../docs/migrating-from-comb.md#page-cursors)).
